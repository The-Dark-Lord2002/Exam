## درس ۱: نمادهای مجانبی و مقایسهٔ رشد

### این درس به چه سؤالی جواب می‌دهد؟
«این الگوریتم با بزرگ شدن ورودی چقدر کند می‌شود؟» ما زمان را با ثانیه اندازه نمی‌گیریم، چون به سرعت کامپیوتر بستگی دارد. به‌جایش **تعداد قدم‌ها** را بر حسب اندازهٔ ورودی (n) می‌شماریم و فقط **شکل رشد** را نگه می‌داریم.

**مثال (چرا فقط شکل رشد؟):** الگوریتم A دقیقاً `100n` قدم و الگوریتم B دقیقاً `n²` قدم برمی‌دارد.
- با `n = 10`: A ⇐ ۱۰۰۰ قدم، B ⇐ ۱۰۰ قدم. B سریع‌تر است.
- با `n = 1000`: A ⇐ ۱۰۰ هزار، B ⇐ یک میلیون. A ده برابر سریع‌تر است.
- از `n = 100` به بعد A همیشه برنده است. برای ورودی‌های بزرگ (که مسئلهٔ واقعی ماست)، ضریب ۱۰۰ مهم نیست؛ مهم این است که یکی «خطی» و دیگری «مربعی» رشد می‌کند.

### نمادها به زبان ساده
نمادها مثل علامت‌های مقایسهٔ عددها هستند، ولی برای **سرعت رشد** توابع: O مثل ≤، Ω مثل ≥، Θ مثل =، o مثل <، ω مثل >. «از یک جایی به بعد» (`n ≥ n₀`) و «با یک ضریب ثابت» (c) یعنی رفتار اول کار و ضریب‌ها را نادیده بگیر.

**شهود:** برای n خیلی بزرگ فقط سریع‌ترین جمله مهم است و ضریب‌ها مهم نیستند. `3n² + 100n` مثل `n²` رفتار می‌کند.

| نماد | معنی ساده | تعریف |
|---|---|---|
| `f = O(g)` | f حداکثر هم‌اندازهٔ g رشد می‌کند (≤) | ثابت‌های `c` و `n₀` هستند که برای `n ≥ n₀`، `f(n) ≤ c·g(n)` |
| `f = Ω(g)` | حداقل (≥) | `f(n) ≥ c·g(n)` |
| `f = Θ(g)` | هم‌اندازه (=) | هم O هم Ω |
| `f = o(g)` | اکیداً کندتر (<) | `f/g → 0` |
| `f = ω(g)` | اکیداً سریع‌تر (>) | `f/g → ∞` |

**مثال برای هر سطر جدول:** `f(n) = 3n² + 100n`.
- **O:** `f = O(n²)` با `c = 4` و `n₀ = 100`، چون `3n² + 100n ≤ 4n²` یعنی `100n ≤ n²` یعنی `n ≥ 100`.
- **Ω:** `f = Ω(n²)` با `c = 3`، چون برای هر n داریم `3n² + 100n ≥ 3n²`.
- **Θ:** هر دو برقرار است، پس `f = Θ(n²)`.
- **o:** `n = o(n²)` چون `n/n² = 1/n → 0`. ولی `f ≠ o(n²)` چون `f/n² → 3`، نه صفر.
- **ω:** `n² = ω(n log n)` چون `n²/(n log n) = n/log n → ∞`.

### چطور نمادها را در تست به کار ببرم؟
1. در هر تابع، **سریع‌ترین جمله** را پیدا کن و ضریبش را بینداز: `5n³ + 2ⁿ` ⇐ `2ⁿ`.
2. دو تابع را با جای‌شان روی نردبان زیر مقایسه کن.
3. اگر روی نردبان نبودند، از هر دو لگاریتم بگیر (بخش بعد).

### نردبان رشد
`1 < log log n < log n < (log n)ᵏ < n^ε < n < n log n < n² < nᵏ < 2ⁿ < 3ⁿ < n! < nⁿ`

**مثال (n = 16، با log در مبنای ۲):** `log log n = 2`، `log n = 4`، `n = 16`، `n log n = 64`، `n² = 256`، `2ⁿ = 65536`، `n! ≈ 2×10¹³`، `nⁿ ≈ 1.8×10¹⁹`.

⚠️ نردبان برای n **خیلی بزرگ** است: در `n = 16`، `(log n)¹⁰ = 4¹⁰ ≈ 10⁶` از `n² = 256` بزرگ‌تر است، ولی بالاخره `n` از هر `(log n)ᵏ` جلو می‌زند.

### ابزار مقایسه: لگاریتم بگیر
**مثال:** `n^(log n)` یا `(log n)ⁿ`؟
لگاریتم اولی `log² n` است و لگاریتم دومی `n · log log n`. دومی خیلی بزرگ‌تر است، پس `(log n)ⁿ` بزرگ‌تر است.
⚠️ اگر لگاریتم‌ها فقط **در ضریب** فرق کنند، نتیجه نگیر: `log 4ⁿ = 2 log 2ⁿ` ولی `4ⁿ ≠ Θ(2ⁿ)`.

### یادآوری لگاریتم (پیش‌نیاز تله‌ها)
`log₂ n` یعنی «چند بار باید ۲ را در خودش ضرب کنم تا به n برسم؟». مثلاً `log₂ 8 = 3` چون `2 × 2 × 2 = 8`، و `log₂ 1024 = 10`. در این کتاب هر جا مبنا ننوشته باشیم، مبنا ۲ است. سه قانون برای همهٔ این بخش کافی است:
- **ضرب ⇐ جمع:** `log(a·b) = log a + log b`. مثال: `log(8 × 4) = 3 + 2 = 5 = log 32`.
- **توانِ داخل ⇐ ضریب بیرون:** `log(aᵏ) = k·log a`. مثال: `log(8²) = 2 × 3 = 6 = log 64`.
- **عوض کردن مبنا فقط یک ضریب ثابت است:** `log₁₀ n = log₂ n / log₂ 10 ≈ 0.3·log₂ n`.

### تله‌ها
1. مبنای log مهم نیست (`log₂ n = Θ(log₁₀ n)`)، ولی **مبنای توان مهم است** (`2ⁿ ≠ Θ(3ⁿ)`).
2. `log n² = 2 log n = Θ(log n)` ولی `log² n = (log n)²` بزرگ‌تر است.
3. **`log(n!) = Θ(n log n)`** و `log(nⁿ) = n log n`؛ این دو Θ هم‌اند.
4. `a^(log_b n) = n^(log_b a)`؛ مثلاً `2^(log₂ n) = n`.
5. `Σ 1/i = Θ(log n)` (هارمونیک)، `Σ iᵏ = Θ(nᵏ⁺¹)`، و در سری هندسی جملهٔ بزرگ غالب است.
6. بعضی توابع **مقایسه‌ناپذیرند**؛ مثلاً اگر توان نوسان کند (مثل `n^(1+sin n)`)، نه O است نه Ω.

### توضیح هر تله با عدد
**مثال (تلهٔ ۱: مبنای log در برابر مبنای توان):** `log₂ n = log₁₀ n / log₁₀ 2 ≈ 3.32·log₁₀ n`؛ نسبت این دو همیشه همان ۳٫۳۲ است (ضریب ثابت) ⇐ Θ برابر. ولی `3ⁿ/2ⁿ = 1.5ⁿ` با بزرگ شدن n به بی‌نهایت می‌رود (برای `n = 10` حدود ۵۸، برای `n = 50` بیش از ۶۰۰ میلیون) ⇐ ضریب ثابت نیست ⇐ Θ متفاوت.

**مثال (تلهٔ ۲: جای توان):** فرق فقط در **جای** توان است:
- `log n²` یعنی `log(n²)`: توان **داخل** log است ⇐ طبق قانون دوم می‌شود `2·log n`؛ فقط یک ضریب ۲ ⇐ `Θ(log n)`.
- `log² n` یعنی `(log n)²`: خودِ جواب log به توان ۲ رسیده ⇐ واقعاً بزرگ‌تر.
- با عدد: `n = 1024` (`log n = 10`): `log n² = 20` ولی `log² n = 100`. با `n ≈ 10⁶` (`log n = 20`): `40` در برابر `400`. نسبت مدام بزرگ‌تر می‌شود، پس `log² n` مرتبهٔ بالاتری دارد.

**مثال (تلهٔ ۳: `log(n!)`):** `n! = 1 × 2 × … × n`. طبق قانون اول، `log(n!) = log 1 + log 2 + … + log n`:
- **سقف:** هر جمله حداکثر `log n` است و n جمله داریم ⇐ `log(n!) ≤ n log n`.
- **کف:** نیمهٔ بزرگ‌تر جمله‌ها (از `n/2` تا n) هر کدام حداقل `log(n/2)` است ⇐ `log(n!) ≥ (n/2)·log(n/2)`، که آن هم از مرتبهٔ `n log n` است.
- پس `log(n!) = Θ(n log n)`. با عدد: `n = 1024`: `log₂(1024!) ≈ 8769`، `n log n = 10240` و کف `512 × 9 = 4608`؛ جواب بین این دو است.
- `log(nⁿ) = n·log n` دقیقاً (قانون دوم). پس **لگاریتمِ** `n!` و `nⁿ` هم‌مرتبه‌اند.

⚠️ این یعنی لگاریتم‌هایشان هم‌مرتبه‌اند، **نه خودشان**. `n!` خیلی کوچک‌تر از `nⁿ` است (`n!/nⁿ → 0`). همان قاعدهٔ «ابزار مقایسه» بالا: وقتی لگاریتم‌ها فقط در ضریب فرق دارند، دربارهٔ خود توابع نتیجه نگیر.

**مثال (تلهٔ ۴: جابه‌جایی پایه و توان):** `a^(log_b n) = n^(log_b a)`. دلیل: از دو طرف `log_b` بگیر؛ هر دو طرف می‌شوند `(log_b n)·(log_b a)`.
- `2^(log₂ n) = n^(log₂ 2) = n¹ = n`.
- `4^(log₂ n) = n^(log₂ 4) = n²`. چک با `n = 8`: `4³ = 64 = 8²` ✓.
- `3^(log₂ n) = n^(log₂ 3) ≈ n^1.585`. این همان زمان الگوریتم کاراتسوبا است.
- **کاربرد:** در قضیهٔ اصلی (درس ۳) تعداد برگ‌های درخت بازگشت `a^(log_b n)` است و همین تبدیل آن را به `n^(log_b a)` می‌رساند.

**مثال (تلهٔ ۵: سه جمع پرکاربرد):**
- **هارمونیک:** `1 + 1/2 + 1/3 + … + 1/n ≈ ln n`. با `n = 1024`: جمع `≈ 7.5` و `ln 1024 ≈ 6.9`؛ هم‌مرتبه‌اند. شهود: جمله‌ها را دسته کن: `1/2`، `1/3 + 1/4`، `1/5 + … + 1/8`، …؛ هر دسته حدود ½ تا ۱ است و تعداد دسته‌ها `log₂ n` است.
- **توان‌ها:** `1 + 2 + … + n = n(n+1)/2 = Θ(n²)` و `1² + 2² + … + n² = n(n+1)(2n+1)/6 = Θ(n³)`. شهود: n جمله، هر کدام حداکثر `nᵏ` ⇐ سقف `nᵏ⁺¹`؛ و نصف جمله‌ها حداقل `(n/2)ᵏ` ⇐ کف هم از همین مرتبه.
- **هندسی:** اگر هر جمله دو برابر قبلی است، **آخرین** جمله غالب است: `1 + 2 + 4 + … + 2ᵏ = 2ᵏ⁺¹ − 1 < 2·2ᵏ`. اگر هر جمله نصف قبلی است، **اولین** جمله غالب است: `1 + 1/2 + 1/4 + … < 2` (یعنی `Θ(1)`).

**مثال (تلهٔ ۶: مقایسه‌ناپذیر):** `f = O(g)` یعنی «از یک جایی به بعد، **همیشه** `f ≤ c·g`». اگر f بالا و پایین برود، ممکن است نه همیشه زیر g بماند نه همیشه بالای آن.
- **مثال ساده:** `f(n) = n` برای n زوج و `f(n) = 1` برای n فرد؛ و `g(n) = √n`. برای n های زوج f از g خیلی بزرگ‌تر است (پس f ≠ `O(g)`) و برای n های فرد خیلی کوچک‌تر (پس f ≠ `Ω(g)`).
- **همان در کتاب:** توان `1 + sin n` بین ۰ و ۲ نوسان می‌کند، پس `n^(1+sin n)` گاهی نزدیک `n²` و گاهی نزدیک ۱ است ⇐ نسبت به n نه O است نه Ω.
- **در تست:** اگر گزینه‌ای مثل «هیچ‌کدام» یا «نه O نه Ω» دیدی و یکی از توابع نوسانی بود (sin، cos، یا تعریف جدا برای زوج و فرد)، جدی بگیرش.

### تمرین درس ۱
1. `log(n!)` از چه مرتبه‌ای است؟
2. درست یا نادرست: `2ⁿ⁺¹ = Θ(2ⁿ)`؛ `2²ⁿ = O(2ⁿ)`.
3. به‌ترتیب صعودی مرتب کن: `n log n`، `n^1.5`، `2^(log₂ n)`، `(log n)¹⁰`
4. `n^(1/log₂ n)` از چه مرتبه‌ای است؟

<details>
<summary>جواب‌ها</summary>

1. `Θ(n log n)`
2. درست؛ نادرست (`2²ⁿ = 4ⁿ`).
3. `(log n)¹⁰ < 2^(log₂ n) = n < n log n < n^1.5`
4. `= 2^(log₂ n / log₂ n) = 2`، یعنی `Θ(1)`.
</details>

## درس ۲: شمردن حلقه‌ها

### این درس به چه سؤالی جواب می‌دهد؟
فقط یک سؤال: **«دستور درونی (مثلاً `x++`) روی هم چند بار اجرا می‌شود؟»** این عدد را بر حسب n می‌نویسیم و طبق درس ۱ فقط جملهٔ بزرگش را نگه می‌داریم. تقریباً هر تست «مرتبهٔ این کد چیست؟» با شش ابزار زیر حل می‌شود.

**روش اصلی کل درس:** برای n کوچک (مثلاً ۸ یا ۱۶) یک **جدول ردگیری** بکش: یک ستون برای مقدارهای متغیر بیرونی و یک ستون برای «حلقهٔ درونی در این دور چند بار اجرا شد». بعد ستون دوم را جمع بزن. همهٔ مثال‌های این درس همین کار را می‌کنند؛ وقتی چند بار با دست انجامش بدهی، الگو را بدون جدول هم می‌بینی.

**مثال (یک حلقهٔ ساده):**
```c
for (i = 1; i <= n; i++)
    x++;
```
با `n = 5`:

| i | ۱ | ۲ | ۳ | ۴ | ۵ |
|---|---|---|---|---|---|
| تعداد اجرای `x++` | ۱ | ۱ | ۱ | ۱ | ۱ |

جمع ۵. در حالت کلی n بار ⇐ `Θ(n)`. اگر گام `i += 3` بود، i مقدارهای `1, 4, 7, …` را می‌گرفت و حدود `n/3` دور می‌شد، که هنوز `Θ(n)` است (ضریب ثابت مهم نیست).

### ابزار ۱: دو حلقهٔ مستقل ⇐ ضرب کن
وقتی حد حلقهٔ درونی **به متغیر بیرونی بستگی ندارد**، حلقهٔ درونی در **هر** دور بیرونی همان تعداد دور را می‌زند. پس تعداد دورها در هم ضرب می‌شوند.

**مثال:**
```c
for (i = 1; i <= n; i++)
    for (j = 1; j <= n; j++)
        x++;
```
با `n = 3`:

| i | j ها | تعداد اجرای `x++` در این دور |
|---|---|---|
| ۱ | ۱، ۲، ۳ | ۳ |
| ۲ | ۱، ۲، ۳ | ۳ |
| ۳ | ۱، ۲، ۳ | ۳ |
| **جمع** | | **۹** |

۹ = `3 × 3`. مثل کلاسی با ۳ ردیف و هر ردیف ۳ صندلی. در حالت کلی `n × n` ⇐ `Θ(n²)`. اگر بیرونی تا n و درونی تا m برود، جواب `n × m` است.

### ابزار ۲: حلقهٔ درونی به i وابسته است ⇐ جمع بزن
**قاعده:** اگر حد حلقهٔ درونی به i بستگی دارد، **ضرب نکن، جمع بزن.** چون طول حلقهٔ درونی در هر دور فرق می‌کند.

**مثال (درونی تا i):**
```c
for (i = 1; i <= n; i++)
    for (j = 1; j <= i; j++)
        x++;
```
با `n = 5`:

| i | j ها | تعداد |
|---|---|---|
| ۱ | ۱ | ۱ |
| ۲ | ۱، ۲ | ۲ |
| ۳ | ۱، ۲، ۳ | ۳ |
| ۴ | ۱ تا ۴ | ۴ |
| ۵ | ۱ تا ۵ | ۵ |
| **جمع** | | **۱۵** |

`1 + 2 + 3 + 4 + 5 = 15 = 5·6/2`. شکل کار یک پلکان است، یعنی تقریباً نصف یک مربع ۵×۵. در حالت کلی `n(n+1)/2 ≈ n²/2` ⇐ `Θ(n²)`.

**مثال (سه شکل رایج همین الگو، با `n = 5`):**

| حلقهٔ درونی | تعداد در دور i | جمع برای n = ۵ | مرتبه |
|---|---|---|---|
| `for (j = 1; j <= i; j++)` | i | `1+2+3+4+5 = 15` | `Θ(n²)` |
| `for (j = i; j <= n; j++)` | `n − i + 1` | `5+4+3+2+1 = 15` | `Θ(n²)` |
| `for (j = 1; j < i; j++)` | `i − 1` | `0+1+2+3+4 = 10` | `Θ(n²)` |

هر سه، پلکانی‌اند و جمعشان حدود `n²/2` است. ⚠️ اینجا ضرب کردن (`n × n`) اتفاقاً همان مرتبه را می‌دهد، ولی در ابزار ۴ جواب غلط می‌دهد؛ پس عادت کن جمع را بنویسی.

### ابزار ۳: متغیر ضرب یا تقسیم می‌شود ⇐ لگاریتم
وقتی i هر دور **در عددی ثابت ضرب** (یا بر آن تقسیم) می‌شود، خیلی سریع به n می‌رسد. سؤال این است: «چند بار باید دو برابر کنم تا از n رد شوم؟» جواب حدود `log₂ n` است.

**مثال (دو برابر شدن):**
```c
for (i = 1; i <= n; i *= 2)
    x++;
```
با `n = 20`: i مقدارهای `1, 2, 4, 8, 16` را می‌گیرد؛ بعد ۳۲ می‌شود که از ۲۰ بیشتر است ⇐ **۵** دور. چک با فرمول: `⌊log₂ 20⌋ + 1 = 4 + 1 = 5`. با `n = 1,000,000` فقط ۲۰ دور. مثل کاغذی که هر بار نصف تا می‌شود.

**مثال (نصف شدن و سه برابر شدن):**

| حلقه | مقدارهای i | تعداد دور |
|---|---|---|
| `for (i = 20; i > 0; i /= 2)` | `20, 10, 5, 2, 1` | ۵ (حدود `log₂ 20`) |
| `for (i = 1; i <= 100; i *= 3)` | `1, 3, 9, 27, 81` | ۵ (حدود `log₃ 100`) |

مبنای log (۲ یا ۳) فقط یک ضریب ثابت است، پس هر دو `Θ(log n)` اند.

**مثال (به توان ۲ رساندن):**
```c
for (i = 2; i <= n; i = i * i)
```
با `n = 300`: i مقدارهای `2, 4, 16, 256` را می‌گیرد؛ بعد `65536` می‌شود ⇐ **۴** دور. هر دور **توانِ** ۲ دو برابر می‌شود (`2¹, 2², 2⁴, 2⁸`)، پس تعداد دورها «لگاریتمِ لگاریتم» است ⇐ `Θ(log log n)`. حتی با `n = 65536` فقط ۵ دور.

### ابزار ۴: بیرونی دو برابر می‌شود و درونی تا i می‌رود ⇐ `Θ(n)`
⚠️ **تلهٔ معروف:** در این کد استدلال «بیرونی `log n` دور × درونی حداکثر n دور = `n log n`» غلط است.
```c
for (i = 1; i <= n; i *= 2)
    for (j = 1; j <= i; j++)
        x++;
```

**مثال (ردگیری با `n = 16`):**

| i | تعداد اجرای درونی (تا i) |
|---|---|
| ۱ | ۱ |
| ۲ | ۲ |
| ۴ | ۴ |
| ۸ | ۸ |
| ۱۶ | ۱۶ |
| **جمع** | **۳۱** |

اگر ضرب می‌کردی: `5 × 16 = 80`. ولی جواب واقعی ۳۱ است، کمتر از `2n = 32`. درونی فقط در **دور آخر** n بار اجرا شد؛ دورهای قبلی خیلی کوچک‌تر بودند.

**چرا همیشه کمتر از 2n؟** در دنبالهٔ دو برابر شونده، هر عدد از جمع همهٔ قبلی‌ها بزرگ‌تر است: `16 > 1 + 2 + 4 + 8 = 15`. پس کل جمع کمتر از دو برابر جملهٔ آخر است. مثل پس‌اندازی که هر ماه دو برابر ماه قبل است: پول ماه آخر از همهٔ ماه‌های قبل روی هم بیشتر است. جواب **`Θ(n)`**.

### ابزار ۵: گام حلقهٔ درونی i است ⇐ هارمونیک ⇐ `Θ(n log n)`
```c
for (i = 1; i <= n; i++)
    for (j = 1; j <= n; j += i)   // ← هر بار i تا جلو می‌پرد
        x++;
```
حلقهٔ درونی از ۱ تا n با پرش‌های i تایی می‌رود، پس حدود `n/i` بار اجرا می‌شود: اول با پرش ۱ (n بار)، بعد با پرش ۲ (نصف)، بعد با پرش ۳ (یک‌سوم)، …

**مثال (ردگیری با `n = 8`):**

| i | j ها | تعداد |
|---|---|---|
| ۱ | ۱، ۲، ۳، …، ۸ | ۸ |
| ۲ | ۱، ۳، ۵، ۷ | ۴ |
| ۳ | ۱، ۴، ۷ | ۳ |
| ۴ | ۱، ۵ | ۲ |
| ۵ | ۱، ۶ | ۲ |
| ۶ | ۱، ۷ | ۲ |
| ۷ | ۱، ۸ | ۲ |
| ۸ | ۱ | ۱ |
| **جمع** | | **۲۴** |

در حالت کلی `n/1 + n/2 + n/3 + … + n/n = n × (1 + 1/2 + … + 1/n) ≈ n × ln n`. چک: `8 × ln 8 ≈ 16.6` و `8 × (1 + ½ + … + ⅛) ≈ 21.7`؛ جواب واقعی ۲۴ از همین مرتبه است (اختلاف به خاطر گرد شدن رو به بالای هر سطر است). جواب `Θ(n log n)`.

💡 **نکتهٔ حفظی:** سری هارمونیک `1 + 1/2 + … + 1/n ≈ ln n`.

### ابزار ۶: شرط با `i*i` ⇐ جذر
```c
i = 1;
while (i * i <= n) i++;
```
**مثال (ردگیری با `n = 20`):** i=1 ⇐ `1 ≤ 20` ✓؛ i=2 ⇐ `4 ≤ 20` ✓؛ i=3 ⇐ `9 ≤ 20` ✓؛ i=4 ⇐ `16 ≤ 20` ✓؛ i=5 ⇐ `25 > 20` ✗. پس **۴** دور، یعنی `⌊√20⌋ = 4`. با `n = 100` ده دور. جواب `Θ(√n)`.

### ترکیب ابزارها
تست‌ها معمولاً دو ابزار را با هم ترکیب می‌کنند. همان جدول ردگیری را بکش.

**مثال (ابزار ۲ + ابزار ۶):**
```c
for (i = 1; i <= n; i++)
    for (j = 1; j * j <= i; j++)
        x++;
```
حلقهٔ درونی برای هر i حدود `√i` بار اجرا می‌شود (ابزار ۶) و چون به i وابسته است، جمع می‌زنیم (ابزار ۲). با `n = 16`:

| i | ۱ تا ۳ | ۴ تا ۸ | ۹ تا ۱۵ | ۱۶ |
|---|---|---|---|---|
| تعداد دور درونی (`⌊√i⌋`) | ۱ | ۲ | ۳ | ۴ |
| سهم در جمع | `3 × 1 = 3` | `5 × 2 = 10` | `7 × 3 = 21` | `1 × 4 = 4` |

جمع `3 + 10 + 21 + 4 = 38`. در حالت کلی `√1 + √2 + … + √n ≈ (2/3)·n^1.5` (برای ۱۶: حدود ۴۳) ⇐ `Θ(n√n)`.

### جدول خلاصهٔ شش الگو
| کد | مرتبه | چرا |
|---|---|---|
| `for(i=1;i<=n;i++) for(j=1;j<=i;j++)` | `Θ(n²)` | `1+2+…+n` |
| `for(i=1;i<=n;i*=2)` | `Θ(log n)` | i دو برابر می‌شود |
| `for(i=2;i<=n;i=i*i)` | `Θ(log log n)` | `i = 2^(2ᵏ)` |
| `for(i=1;i<=n;i*=2) for(j=1;j<=i;j++)` | `Θ(n)` | `1+2+4+…+n < 2n` |
| `for(i=1;i<=n;i++) for(j=1;j<=n;j+=i)` | `Θ(n log n)` | `Σ n/i` هارمونیک |
| `i=1; while(i*i<=n) i++;` | `Θ(√n)` | |

### روش ۴ قدمی برای هر تست
1. **برای هر حلقه:** جمع با عدد ثابت ⇐ حدود n دور؛ ضرب یا تقسیم در عدد ثابت ⇐ `log n`؛ به توان رساندن ⇐ `log log n`؛ شرط `i*i <= n` ⇐ `√n`.
2. **درونی به متغیر بیرونی وابسته است؟** نه ⇐ ضرب کن. بله ⇐ جمع را بنویس.
3. **جمع را با این چهار فرمول ساده کن:** `1+2+…+n ≈ n²/2`؛ `1+2+4+…+n < 2n`؛ `n+n/2+n/4+… < 2n`؛ `n+n/2+n/3+…+1 ≈ n ln n`.
4. **فقط جملهٔ بزرگ را نگه دار.**

💡 **ترفند چک سر جلسه:** تعداد دورها را برای `n = 16` و `n = 32` بشمار و نسبت را ببین. اگر حدود ۲ برابر شد ⇐ `n`؛ حدود ۴ برابر ⇐ `n²`؛ حدود ۲٫۵ برابر ⇐ `n log n`؛ تقریباً ثابت ماند (فقط ۱ واحد بیشتر) ⇐ `log n`. مثلاً ابزار ۴: `31` و `63` (حدود ۲ برابر ⇐ `Θ(n)`)؛ ترکیب بالا: `38` و `110` (حدود ۲٫۹ برابر، نزدیک `2^1.5 ≈ 2.8` ⇐ `n√n`).

### تمرین درس ۲
1. `for(i=n; i>1; i=i/2) for(j=0; j<i; j++) x++;`
2. `for(i=1;i<=n;i++) for(j=1;j<=i;j++) for(k=1;k<=j;k++) x++;`
3. `for(i=1;i<=n;i++) for(j=1;j<=n;j*=2) x++;`

<details>
<summary>جواب‌ها</summary>

1. `n + n/2 + n/4 + … < 2n`، پس `Θ(n)`. (ضرب کردن جواب غلط `n log n` را می‌دهد.)
2. `Σᵢ Σⱼ j = Σ i²/2 ≈ n³/6`، پس `Θ(n³)`.
3. حلقهٔ درونی به i وابسته **نیست**، پس اینجا ضرب درست است: `Θ(n log n)`.
</details>

## درس ۳: قضیهٔ اصلی (Master Theorem)

### این درس به چه سؤالی جواب می‌دهد؟
الگوریتم‌های **تقسیم و حل** (مثل مرتب‌سازی ادغامی) مسئله را به چند تکهٔ کوچک‌تر می‌شکنند، هر تکه را با **خودشان** حل می‌کنند و بعد جواب‌ها را ترکیب می‌کنند. زمانشان یک رابطهٔ بازگشتی است:

`T(n) = a·T(n/b) + f(n)` یعنی: a زیرمسئله، هر کدام به اندازهٔ `n/b`، به‌علاوهٔ `f(n)` کار برای شکستن و ترکیب.

**مثال (خواندن رابطه):** مرتب‌سازی ادغامی آرایه را نصف می‌کند (`b = 2`)، هر نصفه را جدا مرتب می‌کند (`a = 2`) و ادغام دو نیمه n قدم طول می‌کشد (`f(n) = n`) ⇐ `T(n) = 2T(n/2) + n`.

### شهود: دعوای ریشه و برگ‌ها
اگر بازگشت را به شکل درخت بکشی، ریشه `f(n)` کار می‌کند و پایین‌تر گره‌ها زیاد می‌شوند ولی هر کدام کار کمتری دارند. تعداد برگ‌ها `n^(log_b a)` است. پس فقط یک سؤال مانده: **`f(n)` (کار ریشه) بزرگ‌تر است یا `n^c` (کار برگ‌ها)، با `c = log_b a`؟**
- برگ‌ها برنده ⇐ جواب `n^c` (حالت ۱).
- مساوی ⇐ همهٔ `log n` سطح به یک اندازه کار می‌کنند ⇐ `n^c · log n` (حالت ۲).
- ریشه برنده ⇐ جواب `f(n)` (حالت ۳).

**مثال (قدم‌به‌قدم):** `T(n) = 4T(n/2) + n`.
1. `a = 4`، `b = 2` ⇐ `c = log₂ 4 = 2` ⇐ کار برگ‌ها `n²`.
2. کار ریشه `f(n) = n`، که از `n²` چندجمله‌ای کوچک‌تر است (با فاصلهٔ `n¹`).
3. برگ‌ها برنده ⇐ حالت ۱ ⇐ `Θ(n²)`.

برای `T(n) = a·T(n/b) + f(n)` با `a ≥ 1` و `b > 1`:
**قدم ۱:** `c = log_b a` را حساب کن. **قدم ۲:** `f(n)` را با `n^c` مقایسه کن.

### نسخهٔ کلاسیک (سه حالت)
| حالت | شرط | جواب |
|---|---|---|
| ۱ | `f` **چندجمله‌ای کوچک‌تر** از `n^c` است: `f = O(n^(c−ε))` | `Θ(n^c)` |
| ۲ | `f = Θ(n^c)` | `Θ(n^c · log n)` |
| ۳ | `f` **چندجمله‌ای بزرگ‌تر** است: `f = Ω(n^(c+ε))`، و `a·f(n/b) ≤ δ·f(n)` با `δ<1` | `Θ(f(n))` |

**مثال (چرا سه حالت؟ هزینهٔ سطح‌های درخت بازگشت):** در سطح k، تعداد `aᵏ` گره داریم و هر کدام `f(n/bᵏ)` کار می‌کند.
- `8T(n/2) + n²`: سطح k هزینهٔ `8ᵏ·(n/2ᵏ)² = 2ᵏ·n²` دارد ⇐ **رو به افزایش**؛ برگ‌ها غالب‌اند: `Θ(n³)` (حالت ۱).
- `2T(n/2) + n`: هر سطح `2ᵏ·(n/2ᵏ) = n`، و `log n` سطح داریم: `Θ(n log n)` (حالت ۲).
- `2T(n/2) + n²`: سطح k هزینهٔ `n²/2ᵏ` دارد ⇐ **رو به کاهش**؛ ریشه غالب است: `Θ(n²)` (حالت ۳). شرط نظم: `2·(n/2)² = n²/2 ≤ ½·n²` ✓.

⚠️ **مهم برای تست:** وقتی `f` فقط به اندازهٔ یک ضریب `log` با `n^c` فرق دارد (مثل `n log n` در برابر `n`)، در هیچ‌کدام از سه حالت کلاسیک نمی‌افتد. اگر تست بپرسد «کدام را **نمی‌توان مستقیماً** با قضیهٔ اصلی حل کرد»، منظورش همین شکاف است (سؤال ۸ آزمون فصل).

### حالت ۲ گسترده (برای پیدا کردن جواب)
اگر `f = Θ(n^c · logᵏ n)`:

| k | جواب |
|---|---|
| `k > −1` | `Θ(n^c · logᵏ⁺¹ n)` |
| `k = −1` | `Θ(n^c · log log n)` |
| `k < −1` | `Θ(n^c)` |

**مثال (با `2T(n/2) + f`، یعنی `c = 1`):**
- `f = n·log n` (`k = 1`): جمع سطح‌ها `n·(log n + (log n − 1) + … + 1) ≈ n·log² n / 2` ⇐ `Θ(n log² n)`.
- `f = n/log n` (`k = −1`): جمع سطح‌ها `n·(1/log n + … + 1/2 + 1)` یک سری هارمونیک با `log n` جمله است ⇐ `Θ(n log log n)`.
- `f = n/log² n` (`k = −2`): سری `Σ 1/j²` همگراست ⇐ `Θ(n)`.

### مثال‌ها
| رابطه | c | جواب |
|---|---|---|
| `2T(n/2) + n` | 1 | حالت ۲: `Θ(n log n)` (مرتب‌سازی ادغامی) |
| `T(n/2) + 1` | 0 | حالت ۲: `Θ(log n)` (جستجوی دودویی) |
| `8T(n/2) + n²` | 3 | حالت ۱: `Θ(n³)` |
| `2T(n/2) + n²` | 1 | حالت ۳: `Θ(n²)` |
| `2T(n/2) + n log n` | 1 | گسترده با k=1: `Θ(n log² n)` |

### تمرین درس ۳
1. `9T(n/3) + n²`
2. `3T(n/4) + n log n`
3. `7T(n/2) + n²`
4. `2T(n/4) + √n`
5. `2T(n/2) + n/log n`
6. `4T(n/2) + n² log n`

<details>
<summary>جواب‌ها</summary>

1. `c=2`، حالت ۲: `Θ(n² log n)`
2. `c ≈ 0.79`، حالت ۳ و شرط نظم برقرار است: `Θ(n log n)`
3. `c = log₂ 7 ≈ 2.81`، حالت ۱: `Θ(n^2.81)` (استراسن)
4. `c = 1/2`، حالت ۲: `Θ(√n log n)`
5. گسترده با k=−1: `Θ(n log log n)` (در نسخهٔ کلاسیک مستقیم حل نمی‌شود)
6. گسترده با k=1: `Θ(n² log² n)` (در نسخهٔ کلاسیک مستقیم حل نمی‌شود)
</details>

## درس ۴: سایر روش‌های حل رابطهٔ بازگشتی

### این درس به چه سؤالی جواب می‌دهد؟
قضیهٔ اصلی فقط شکل `a·T(n/b) + f(n)` را حل می‌کند؛ یعنی وقتی مسئله به تکه‌های **هم‌اندازه** شکسته می‌شود. ولی در تست‌ها رابطه‌هایی می‌آید مثل `T(n/3) + T(2n/3) + n` (تکه‌های نامساوی)، `T(√n)` (جذر) یا `T(n−1)` (یکی‌یکی کم شدن). این درس برای هر کدام یک ابزار می‌دهد.

**ایدهٔ مشترک همه:** رابطهٔ بازگشتی می‌گوید «کار کل = کار همین مرحله + کار زیرمسئله‌ها». اگر همهٔ مرحله‌ها را باز کنی و کارشان را **جمع بزنی**، جواب به دست می‌آید. ابزارهای زیر فقط راه‌های سریع برای این جمع زدن‌اند.

**مثال (باز کردن ساده):** `T(n) = T(n−1) + 1` با `T(0) = 0`: `T(n) = 1 + T(n−1) = 1 + 1 + T(n−2) = … = n` ⇐ `Θ(n)`. هر قدم ۱ واحد کار دارد و n قدم داریم.

### نقشهٔ انتخاب ابزار
| شکل رابطه | ابزار |
|---|---|
| `aT(n/b) + f` | قضیهٔ اصلی (درس ۳) |
| تقسیم نامساوی: `T(αn) + T(βn) + …` | درخت بازگشت یا آکرا-بازی |
| `T(√n)` | تغییر متغیر |
| `T(n−1)` یا `T(n−c)` | باز کردن و جمع زدن |

### الف) درخت بازگشت
برای `T(n) = T(αn) + T(βn) + Θ(n)`:
- اگر `α+β < 1` جواب `Θ(n)` است.
- اگر `α+β = 1` جواب `Θ(n log n)` است (هزینهٔ هر سطح n و عمق `log n`).
- اگر `α+β > 1` از آکرا-بازی استفاده کن.

**مثال:**
- `T(n) = T(n/3) + T(2n/3) + n`: هر سطح کامل درخت هزینهٔ n دارد و عمق `log_{3/2} n` است ⇐ `Θ(n log n)`.
- `T(n) = T(n/2) + T(n/4) + n`: هزینهٔ سطح‌ها `n, 3n/4, 9n/16, …` است (سری هندسی نزولی) ⇐ `Θ(n)`.

### ب) آکرا-بازی (ابزار نهایی تقسیم‌های نامساوی)
برای `T(x) = Σ aᵢ·T(bᵢ·x) + g(x)`:
1. عدد p را طوری پیدا کن که `Σ aᵢ · bᵢᵖ = 1`. (ترفند: اول توان g را امتحان کن.)
2. جواب `Θ( xᵖ · (1 + ∫₁ˣ g(u)/u^(p+1) du) )` است.

انتگرال‌های لازم: `∫du/u = ln x`، `∫du/(u ln u) = ln ln x`.
**نتیجهٔ عملی:** اگر `g = xᵖ · logᵏ x` باشد، همان جدول «حالت ۲ گسترده» با `c = p` جواب را می‌دهد.

**مثال:**
- `T(n) = 2T(n/4) + T(n/2) + n`: توان g را امتحان کن، `p = 1`: `2·(1/4) + 1/2 = 1` ✓. پس `g = n¹·log⁰ n` با `k = 0` ⇐ `Θ(n log n)`.
- `T(n) = 2T(n/2) + 8T(n/4) + n` (اینجا `2·½ + 8·¼ = 3 > 1`): `p = 2` چون `2·(1/4) + 8·(1/16) = 1` ✓. انتگرال `∫₁ⁿ u/u³ du = 1 − 1/n` کراندار است ⇐ `Θ(n²)`.

### ج) تغییر متغیر (وقتی `√n` دیدی)
قرار بده `n = 2ᵐ` و `S(m) = T(2ᵐ)`.
- `T(n) = 2T(√n) + log n` تبدیل می‌شود به `S(m) = 2S(m/2) + m`، پس `S = m log m` و `T = Θ(log n · log log n)`.
- `T(n) = T(√n) + 1` تبدیل می‌شود به `S(m) = S(m/2) + 1`، پس `T = Θ(log log n)`.
- **ترفند تقسیم:** برای `T(n) = √n·T(√n) + n` اول دو طرف را بر n تقسیم کن و `R(n) = T(n)/n` بگذار.

### د) کم‌شونده‌ها
| رابطه | جواب |
|---|---|
| `T(n−1) + 1` | `Θ(n)` |
| `T(n−1) + n` | `Θ(n²)` |
| `T(n−1) + log n` | `Θ(n log n)` |
| `T(n−1) + 1/n` | `Θ(log n)` |
| `2T(n−1) + 1` | `Θ(2ⁿ)` (هانوی) |
| `T(n−1) + T(n−2)` | `Θ(φⁿ)` با `φ ≈ 1.618` (فیبوناچی) |
| `T(n−1) + 2T(n−2) + T(n−3)` | ریشهٔ معادلهٔ `x³ = x² + 2x + 1` (≈ 2.15)؛ پس **کران ساده** `3ⁿ` است |

**مثال (باز کردن):** `T(n) = T(n−1) + n` با `T(1) = 1`:
`T(n) = n + (n−1) + T(n−2) = … = n + (n−1) + … + 1 = n(n+1)/2 = Θ(n²)`.
به همین ترتیب `T(n−1) + log n` می‌شود `log 1 + … + log n = log(n!) = Θ(n log n)`، و `2T(n−1) + 1` با `T(1) = 1` می‌شود `1, 3, 7, 15, …` یعنی `2ⁿ − 1`.

### تمرین درس ۴
1. `T(n) = T(n/2) + T(n/4) + T(n/8) + n`
2. `T(n) = T(n/4) + T(3n/4) + n`
3. `T(n) = √n · T(√n) + n`
4. `T(n) = 2T(√n) + 1`
5. `T(n) = T(n−2) + n`

<details>
<summary>جواب‌ها</summary>

1. `1/2 + 1/4 + 1/8 = 7/8 < 1`، پس `Θ(n)`.
2. `1/4 + 3/4 = 1`، پس `Θ(n log n)`.
3. `R(n) = R(√n) + 1`، پس `R = log log n` و `T = Θ(n log log n)`.
4. `S(m) = 2S(m/2) + 1`، پس `S = Θ(m)` و `T = Θ(log n)`.
5. `n + (n−2) + (n−4) + … ≈ n²/4`، پس `Θ(n²)`.
</details>

## درس ۵: تحلیل سرشکن (Amortized)

### از صفر: قلک پس‌انداز
آرایهٔ پویا (مثل `vector` یا `ArrayList`) وقتی پر شود، آرایهٔ دو برابر بزرگ‌تری می‌گیرد و همه را کپی می‌کند. پس **بیشتر** درج‌ها ارزان‌اند (۱ قدم) ولی **گاهی** یک درج خیلی گران است (کپی همه). سؤال: «به‌طور میانگین هر درج چقدر خرج دارد؟»

**تشبیه:** هر بار که درج ارزان می‌کنی، ۲ سکهٔ اضافه در قلک می‌گذاری. وقتی نوبت کپی گران رسید، هزینه‌اش را از قلک می‌دهی. اگر ثابت کنی قلک **هیچ‌وقت منفی نمی‌شود**، یعنی هر عمل به‌طور میانگین فقط ۳ سکه خرج دارد، یعنی `O(1)`، حتی با اینکه بعضی عمل‌ها تکی گران‌اند.

**مثال:** ۸ درج با ظرفیت اولیهٔ ۱: کپی‌ها در اندازه‌های ۱، ۲ و ۴ ⇐ `1 + 2 + 4 = 7` کپی. کل کار `8 + 7 = 15`، یعنی کمتر از ۲ واحد برای هر درج.

**شهود:** میانگین هزینه روی **بدترین دنبالهٔ n عمل**. این تحلیل احتمالاتی نیست و تحلیل حالت متوسط هم نیست؛ تضمین بدترین حالت است.

| مثال | تحلیل | هزینهٔ سرشکن |
|---|---|---|
| آرایهٔ پویا با **دو برابر** شدن | کپی‌ها `1+2+4+…+n < 2n` | `O(1)` |
| آرایهٔ پویا با **اضافهٔ ثابت** (مثلاً +۱۰۰) | کپی‌ها `Θ(n²)` | `Θ(n)` |
| شمارندهٔ دودویی (فقط افزایش) | بیت i هر `2ⁱ` بار عوض می‌شود؛ جمع `< 2n` | `O(1)` |
| پشته با MULTIPOP | هر عنصر حداکثر یک push و یک pop دارد | `O(1)` |

**مثال برای هر سطر جدول:**
- **دو برابر شدن:** ۹ درج با ظرفیت اولیهٔ ۱: کپی در اندازه‌های ۱، ۲، ۴، ۸ ⇐ `15` کپی؛ کل کار `9 + 15 = 24 < 3×9`.
- **اضافهٔ ۱۰۰:** با ۱۰۰۰ درج، کپی در اندازه‌های ۱۰۰، ۲۰۰، …، ۹۰۰ ⇐ `100 + 200 + … + 900 = 4500` کپی. این عدد با `n²/200` رشد می‌کند.
- **شمارنده:** ۸ افزایش از ۰: تعداد بیت‌های عوض‌شده `1, 2, 1, 3, 1, 2, 1, 4` است، جمعاً `15 < 2×8`.
- **MULTIPOP:** ۵ push، `MULTIPOP(3)`، ۲ push، `MULTIPOP(10)`: کل pop ها حداکثر به تعداد push ها، یعنی ۷ است؛ پس ۹ عمل روی هم حداکثر ۱۴ واحد کار دارند.

**سه روش:**
- **تجمعی:** کل هزینه تقسیم بر n.
- **حسابداری:** عمل‌های ارزان پیش‌پرداخت می‌دهند تا عمل‌های گران پوشش داده شوند؛ اعتبار هیچ‌وقت منفی نمی‌شود.
- **پتانسیل:** هزینهٔ سرشکن = هزینهٔ واقعی + `ΔΦ`. مثلاً در شمارنده با Φ = تعداد بیت‌های ۱، هر increment هزینهٔ سرشکن ۲ دارد.

**مثال:**
- **حسابداری (پشته):** برای هر push دو سکه بگیر: یکی خرج خود push، یکی ذخیره روی عنصر برای pop آینده. MULTIPOP از سکه‌های ذخیره پرداخت می‌شود.
- **پتانسیل (شمارنده):** `0111 → 1000`: هزینهٔ واقعی ۴ (چهار بیت عوض شد) و Φ از ۳ به ۱ رسید (`ΔΦ = −2`)، پس هزینهٔ سرشکن `4 − 2 = 2`.

### تمرین درس ۵
1. آرایهٔ پویا هر بار که پر شد **سه برابر** می‌شود. هزینهٔ سرشکن هر درج؟
2. شمارندهٔ k بیتی که هم increment و هم decrement دارد. هزینهٔ سرشکن هر عمل در بدترین دنباله؟

<details>
<summary>جواب‌ها</summary>

1. `O(1)` (هر ضریب ثابت بزرگ‌تر از ۱ کافی است).
2. `Θ(k)`. دنبالهٔ متناوب increment و decrement روی مرز `0111…1 ↔ 1000…0` هر بار k بیت را عوض می‌کند. تحلیل `O(1)` فقط برای افزایش تنها درست است.
</details>

## 🗂 کارت خلاصهٔ فصل ۱
- **نردبان:** `1 < log log n < log n < n^ε < n < n log n < nᵏ < 2ⁿ < n! < nⁿ`
- `log(n!) = Θ(n log n) = Θ(log nⁿ)`؛ `log n² = Θ(log n)` ولی `log² n` بزرگ‌تر است. توان نوسانی یعنی مقایسه‌ناپذیر.
- **حلقه:** حلقهٔ وابسته را جمع بزن. `i*=2` یعنی `log n`؛ `i=i*i` یعنی `log log n`؛ `j+=i` یعنی هارمونیک.
- **قضیهٔ اصلی:** `c = log_b a`. سه حالت کلاسیک «چندجمله‌ای» فاصله می‌خواهند. فاصلهٔ `log` در نسخهٔ کلاسیک «مستقیم حل نمی‌شود»؛ جوابش را با حالت گسترده بگیر (`k>−1`: `logᵏ⁺¹`؛ `k=−1`: `log log`؛ `k<−1`: `n^c`).
- **تقسیم نامساوی:** اگر `Σα<1` جواب `n` است؛ اگر `=1` جواب `n log n`؛ در غیر این صورت آکرا-بازی (`Σ aᵢbᵢᵖ = 1`).
- **`√n`:** قرار بده `n = 2ᵐ`. **`T(n/log n)`:** جواب `log n / log log n`.
- **سرشکن:** دو برابر کردن `O(1)`، اضافهٔ ثابت `Θ(n)`، شمارندهٔ دوطرفه `Θ(k)`.
