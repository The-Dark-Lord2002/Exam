## درس ۱: ساختار تابع بازگشتی و ترتیب چاپ

### از صفر: صف سینما
در صف طولانی سینما ایستاده‌ای و می‌خواهی بدانی نفر چندمی. جلو را نمی‌بینی. از نفر جلویی می‌پرسی «تو نفر چندمی؟». او هم نمی‌داند و از جلویی خودش می‌پرسد … تا به **نفر اول** می‌رسد که بدون پرسیدن می‌داند: «من اولم». بعد جواب‌ها برمی‌گردند: «من دومم»، «من سومم»، … تا به تو برسد.

این دقیقاً **بازگشت** است: تابعی که برای حل مسئله، **خودش را روی نسخهٔ کوچک‌تر همان مسئله** صدا می‌زند.
- **حالت پایه:** جایی که بدون پرسیدن جواب معلوم است (نفر اول). بدون آن، پرسیدن تا ابد ادامه پیدا می‌کند و برنامه از کار می‌افتد.
- **قدم بازگشتی:** مسئله را کوچک‌تر کن، از خودت بپرس، و جواب را کامل کن (یکی به جواب جلویی اضافه کن).

### یک تابع بازگشتی ساده
```c
int s(int n) {               // جمع ۱ تا n
    if (n == 0) return 0;    // حالت پایه
    return n + s(n - 1);     // قدم بازگشتی
}
```

**مثال (ردگیری `s(4)`):**
```
s(4) = 4 + s(3)
           s(3) = 3 + s(2)
                      s(2) = 2 + s(1)
                                 s(1) = 1 + s(0)
                                            s(0) = 0   ← پایه
```
حالا برگشت از پایین به بالا: `s(1) = 1`، `s(2) = 3`، `s(3) = 6`، `s(4) = 10`.

### هر فراخوانی جعبه‌های خودش را دارد
هر بار که تابع صدا زده می‌شود، یک **قاب** تازه روی **پشتهٔ فراخوانی** ساخته می‌شود با n و متغیرهای محلی **مخصوص خودش**. n در `s(4)` و n در `s(3)` دو جعبهٔ جدا هستند. وقتی یک فراخوانی تمام می‌شود، قابش برداشته می‌شود و اجرا دقیقاً از همان نقطه‌ای که در قاب قبلی متوقف شده بود ادامه پیدا می‌کند.

**مثال (پشتهٔ فراخوانی برای `fact(3)`):** با `fact(n) = n × fact(n−1)` و `fact(1) = 1`:
- رفت: `fact(3)` صبر می‌کند تا `fact(2)` تمام شود؛ `fact(2)` صبر می‌کند تا `fact(1)`.
- `fact(1)` حالت پایه است و ۱ برمی‌گرداند.
- برگشت: `fact(2) = 2 × 1 = 2`، بعد `fact(3) = 3 × 2 = 6`. در اوج، ۳ قاب روی پشته بود و هر کدام n خودش را داشت.

### ترتیب چاپ: رفت یا برگشت؟
تست‌های این فصل بیشتر می‌پرسند «خروجی چیست؟». کلید جواب، جای printf نسبت به فراخوانی بازگشتی است.

**قاعدهٔ طلایی ترتیب چاپ:**
- چاپ **قبل** از فراخوانی ⇐ در مسیر **رفت** چاپ می‌شود (ترتیب نزولی).
- چاپ **بعد** از فراخوانی ⇐ در مسیر **برگشت** چاپ می‌شود (ترتیب صعودی).

```c
void p(int n) { if (n == 0) return; printf("%d ", n); p(n-1); }   // p(3): 3 2 1
void q(int n) { if (n == 0) return; q(n-1); printf("%d ", n); }   // q(3): 1 2 3
void r(int n) { if (n <= 0) return; printf("%d ", n); r(n-2); printf("%d ", n); }
// r(5): 5 3 1 1 3 5   (یک بار در رفت، یک بار در برگشت)
```

**مثال (چرا q صعودی چاپ می‌کند؟):** `q(3)` قبل از چاپ کردن، `q(2)` را صدا می‌زند و منتظر می‌ماند؛ `q(2)` منتظر `q(1)`؛ `q(1)` منتظر `q(0)` که فوراً برمی‌گردد. حالا `q(1)` به خط چاپ می‌رسد ⇐ «۱»، بعد برمی‌گردد و `q(2)` چاپ می‌کند ⇐ «۲»، و آخر `q(3)` ⇐ «۳». **کسی که اول صدا زده شده، آخر از همه چاپ می‌کند.**

**روش:** درخت فراخوانی را بکش (هر فراخوانی یک گره، فرزندانش فراخوانی‌هایی که انجام می‌دهد). کنار هر گره بنویس printf «قبل» از فرزندان است یا «بعد». بعد درخت را از ریشه، چپ به راست پیمایش کن و چاپ‌ها را به همان ترتیب بنویس.

### تمرین درس ۱
```c
// 1
int g(int n) { if (n == 0) return 0; return n % 10 + g(n / 10); }      // g(1234)?
// 2
void b(int n) { if (n > 1) b(n / 2); printf("%d", n % 2); }            // b(13)?
```

## درس ۲: شمردن فراخوانی‌ها و توابع کلاسیک

### از صفر: چرا بعضی توابع بازگشتی منفجر می‌شوند؟
اگر هر فراخوانی **یک بار** خودش را صدا بزند (مثل s و fact)، فراخوانی‌ها یک زنجیرند و تعدادشان حدود n است. اگر هر فراخوانی **دو بار** خودش را صدا بزند، درخت فراخوانی دوشاخه می‌شود و تعداد گره‌ها می‌تواند **نمایی** رشد کند.

**مثال (درخت `fib(4)`):** با `fib(n) = fib(n−1) + fib(n−2)` و پایه‌های `fib(0)` و `fib(1)`:
```
                fib(4)
           /            \
       fib(3)          fib(2)
       /    \          /    \
   fib(2)  fib(1)  fib(1)  fib(0)
   /    \
fib(1) fib(0)
```
۹ گره، یعنی ۹ فراخوانی. `fib(2)` دو بار از نو حساب شده است. برای n های بزرگ این تکرار بیهوده انفجاری می‌شود (همین مشکل را در ساختمان داده با «برنامه‌نویسی پویا» حل می‌کنند).

**روش شمردن:** رابطهٔ «تعداد فراخوانی» را بنویس: `C(n) = 1 + C(زیرمسئله‌ها)`؛ «۱» برای خود فراخوانی. مثلاً برای فیبوناچی `C(n) = 1 + C(n−1) + C(n−2)` و `C(0) = C(1) = 1`.

| تابع | تعداد فراخوانی یا هزینه |
|---|---|
| فاکتوریل `f(n) = n·f(n−1)` | n فراخوانی، `O(n)` |
| فیبوناچی ساده `fib(n) = fib(n−1) + fib(n−2)` | **`2·F(n+1) − 1`** فراخوانی (نمایی). مثلاً `fib(5)`: ۱۵ و `fib(6)`: ۲۵ |
| هانوی | `2ⁿ − 1` حرکت |
| ب.م.م اقلیدسی `gcd(b, a % b)` | `O(log min(a,b))` |
| توان سریع `t = pw(x, n/2)` و بعد `t·t` | `O(log n)` ضرب |
| `h(n) = h(n/2) + h(n/2)` (دو فراخوانی **جدا**) | `2n − 1` فراخوانی برای n توان ۲ |

**مثال برای هر سطر جدول:**
- **فیبوناچی:** `C(2) = 1 + 1 + 1 = 3`، `C(3) = 1 + 3 + 1 = 5`، `C(4) = 1 + 5 + 3 = 9`، `C(5) = 15`. چک با فرمول: `2·F(5) − 1 = 2·5 − 1 = 9` برای `fib(4)` ✓ (همان ۹ گره درخت بالا).
- **دو فراخوانی جدا:** `h(4)` ⇐ دو `h(2)` ⇐ چهار `h(1)`. جمع `1 + 2 + 4 = 7 = 2·4 − 1` ✓.
- **ب.م.م:** `gcd(48, 18)` ⇐ `gcd(18, 12)` ⇐ `gcd(12, 6)` ⇐ `gcd(6, 0)`: ۴ فراخوانی.
- **توان سریع:** `pw(2, 10)` ⇐ `pw(2, 5)` ⇐ `pw(2, 2)` ⇐ `pw(2, 1)` ⇐ `pw(2, 0)`: ۵ فراخوانی و جواب ۱۰۲۴.
- **هانوی:** با ۳ دیسک، `2³ − 1 = 7` حرکت.

⚠️ `pw(x, n/2) * pw(x, n/2)` (دو بار صدا زدن) با `t = pw(x, n/2); t * t` (یک بار) فرق دارد. اولی درخت دوشاخه می‌سازد و `O(n)` است؛ دومی زنجیر است و `O(log n)`.

### متغیر static در بازگشت
گفتیم هر قاب جعبه‌های **خودش** را دارد. استثنا: متغیر `static` فقط **یک** جعبه است که بین **همهٔ** فراخوانی‌ها مشترک است (فصل ۳).

**مثال:**
```c
int fs(int n) { static int c = 0; c++; if (n > 0) fs(n - 1); return c; }
printf("%d", fs(3));   // 4
```
`fs(3)`، `fs(2)`، `fs(1)` و `fs(0)` هر کدام همان یک c را زیاد می‌کنند. وقتی `fs(3)` به return می‌رسد، c برابر ۴ است. اگر c معمولی (غیر static) بود، جواب ۱ می‌شد.

## 🗂 کارت خلاصهٔ فصل ۴
- چاپ قبل از فراخوانی: رفت (نزولی). چاپ بعد از فراخوانی: برگشت (صعودی). هر دو: الگوی آینه‌ای.
- تعداد فراخوانی را با `C(n) = 1 + Σ C(زیرمسئله)` بشمار. فیبوناچی: `2F(n+1) − 1`.
- دو بار صدا زدن زیرمسئلهٔ یکسان، هزینه را چند برابر می‌کند. یک بار صدا زدن و ذخیره کردن، `O(log n)` می‌دهد.
- static بین همهٔ قاب‌ها مشترک است. تابع ۹۱: همیشه ۹۱ برای `x ≤ 101`.
